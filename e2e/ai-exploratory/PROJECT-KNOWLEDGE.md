# 项目认知基座（AI 测试用）

> 本文档是 AI 测试代理（以及人类测试者）理解本系统的"上下文包"。
> 测试的任何推理都必须建立在这些事实上，而不是凭空猜测。
> 最后更新：2026-08-18（随代码变更同步维护）

## 1. 系统定位

科室管理一站式工作台（智能周报系统）：部门级周报填报、协作、汇总、AI 分析平台。
React+Vite 前端（5173 dev / Tomcat 或 nginx 生产），Spring Boot 后端（8080），SQLite（生产规划迁 TDSQL MySQL）。

## 2. 核心业务规则（不可变的业务语义）

1. **周报周期**：以周五日期 `YYYYMMDD` 为周期标签。当前周 = 今天所在周的周五（周六日取下周五）。
2. **重点/常规工作**：同一 `content` 数组内按 `highlighted` 布尔分区展示；根任务序号按分区位置**显示时动态生成**（不存序号在文本里）。
3. **截止时间**：默认周五 20:00（可自定义），截止后普通用户不可编辑（`locked`/deadlinePassed）；超管永远可编辑。
4. **继承**：创建新周期时，`本周工作 = 上周的下周计划`（**创建时刻的快照复制**，非活链接）；查找"上周"= 严格小于目标周的最近有数据的周。
5. **软删除（回收站）**：删除周期 = 给所有行打 `deleted_at` 标记。数据不删，超管可在回收站一键恢复。**已删周期对所有常规查询不可见，包括"当前周"**。
6. **提交**：提交 = 往 `submissions` JSON 追加版本快照；历史周锁定。
7. **权限**：超管=工号 33528（前后端判定方式不同：前端 `getCurrentUser().id`（=username），后端 `currentUser.username`）。普通管理员拥有除用户/权限管理外全部权限，但删除周期仅限"当前周之后"的周。

## 3. 关键状态模型（bug 高发区）

### 3.1 前端内存状态（data.ts 模块级）
- `_reports: WeeklyReport[]` —— 全量周报缓存（后端 + 前端固化历史周 ≤20260529）
- `_deletedWeeks: Set<string>` —— 回收站周期集合（`GET /reports/deleted-weeks` 拉取）
- 周下拉框选项 = `_reports.weekLabel ∪ {当前周} − _deletedWeeks`

### 3.2 页面状态（WeeklyReportV2）
- `selectedWeek`：有三个写入源——①初始化默认当前周、②URL 参数 `?weekLabel=`、③删除后回退。**任何写入源都必须检查回收站状态**（20260821 bug 的教训）。
- `report.content: TaskItem[]` 与 `nextPlanTasks: TaskItem[]`：两个并行任务树状态，保存时序列化合并。
- `isUserEditingRef`：决定是否触发自动保存；非用户编辑的状态同步不得触发保存。

### 3.3 多人协作
- 乐观锁：`updated_at` 版本比对，冲突 → 三向合并弹窗。
- 30 秒轮询发现服务端更新 → stale 提示。
- `syncNextWeek`：编辑本周 nextPlan 会**直接覆盖**下周 content（无冲突检查——已知风险 R3c）。

## 4. 已修复的 bug 家族（模式，必须防回归）

| 家族 | 模式 | 实例 |
|---|---|---|
| 状态双写不同步 | 同一事实有两个状态源，只改了一个 | ①序号分组 `highlighted===`（undefined vs false）②0821 初始化选周未查回收站 ③URL 参数选周未查回收站 |
| 时间边界 | 周期/截止的计算依赖"现在" | 周末当前周=下周五、截止瞬间 editable 未刷新、前后端时区 |
| 快照与活引用混淆 | 以为是快照其实是引用/反之 | 继承是快照但 syncNextWeek 是活的覆盖 |
| 权限判定不一致 | 前后端、不同页面的判定逻辑不一致 | 超管前端 id(=username) vs 后端 username；普通管理员删除周期仅限未来周 |

## 5. 数据红线

- 测试只能在专用周期 `20260904` + 测试账号 `e2e_test` 上写入；真实周期只读。
- 用户密码（bcrypt）绝不可被任何初始化/迁移逻辑覆盖。
- 软删除数据必须可 100% 恢复（含批注、提交快照、锁定状态）。
