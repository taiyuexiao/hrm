# 风险台账（从设计推理出的潜在 bug）

> 方法：不从"测什么"出发，而从"什么地方会出错"出发。
> 每条风险 = 推理链（为什么可能错）+ 验证方式 + 状态。
> 状态：✅已修复已加回归 / 🐞已确认待修 / 🔍待验证 / ⚠️已知设计取舍 / ❌推理错误（已排除）

## 家族一：状态双写不同步（同一事实多个状态源）

### R1a 初始化选周未查回收站 ✅
- 推理：`selectedWeek` 初始化=当前周，与"下拉框过滤已删周"是两个逻辑，只改了一个。
- 实例：删除当前周 0821 后重新登录 → 默认仍选中 0821 + 自动保存报错。
- 验证：WebBridge 实测复现 → 已修复 → 回归用例 `tests/10-recycle-current-week.spec.ts`。

### R1b URL 参数选周未查回收站 🐞（已确认，同家族第二实例）
- 推理：修复 R1a 后审查其余写入源，发现 `useState(urlWeek)` 和 `searchParams` effect 也无回收站检查。
- 触发：从通知消息跳转 `/?weekLabel=<已删周期>`，或书签/历史记录中带已删周期。
- 预期现象：与 R1a 相同（空白页 + 自动保存报错）。
- 验证：E2E 用例 `tests/11-recycle-url-week.spec.ts`。

### R1c 已删周期的本地草稿恢复 🔍
- 推理：草稿恢复（loadDraft）按 weekLabel 匹配，不查回收站；若周期在回收站中，恢复草稿 → 编辑 → 保存被拒。
- 预期：草稿恢复弹窗对已删周期应被抑制或给出明确引导。
- 验证：先构造"周期有草稿→删除周期→重新打开"场景。

### R1d 通知中心跳转到已删周期 🔍
- 推理：通知里存的是 weekLabel+dept，点击后 URL 参数跳转（=R1b 路径），且通知本身在周期删除后依然展示。
- 验证：对测试周期制造一条 @ 通知 → 删除周期 → 点通知。

### R1e 演示模式/提交管理页是否过滤已删周 🔍
- 推理：这些页面若不经 `getDynamicWeekOptions` 而直接读 `_reports`，过滤是一致的（后端已滤）；但若读其他来源（submissions 统计）可能不一致。
- 验证：删除有提交记录的周期 → 检查提交管理页计数。

## 家族二：时间边界（依赖"现在"的计算）

### R2a 截止瞬间 editable 不刷新 🔍
- 推理：`editable` 由 `deadlinePassed` 决定，而后端时间戳每小时（3600000ms）才拉一次；用户 19:59 打开页面编辑，20:00 后页面不重载 → 前端仍显示可编辑 → 自动保存被后端拒绝（可能反复弹错）。
- 验证：将测试周期 deadline 设为 1 分钟后 → 等过期 → 观察编辑与保存行为。

### R2b 周末"伪自动创建" ⚠️（已知设计取舍）
- 推理：周六日当前周=下周五 + 下拉框保底当前周 + 继承构造有内容的空白报告 → 任意小编辑（含勾选复选框）触发自动保存 → 周期被"自动"创建。
- 现状：已分析确认机制存在，待产品决策是否改。

### R2c 前后端时区不一致 🔍
- 推理：前端当前周用浏览器本地时区，后端 DeadlineCalculator 用 Asia/Shanghai；跨时区用户看到/被允许的操作不一致。
- 验证：改系统时区后观察当前周与截止判定。

## 家族三：快照与活引用混淆

### R3c syncNextWeek 无冲突覆盖下周 ⚠️（已确认设计风险）
- 推理：编辑本周 nextPlan 时 `syncNextWeek` 直接 `saveReport(下周)`，不走乐观锁/合并；若下周内容已被他人填写，会被静默覆盖。
- 验证：A 填下周内容 → B 编辑上周 nextPlan → 检查下周内容是否被覆盖。

## 家族四：权限判定不一致

### R4a 超管 ID 判定 ❌（推理错误，已排除）
- 推理：`isSuperAdmin` 比较 `user.id === '33528'`，而后端登录返回 DB 自增 id（6）。
- 验证：`getCurrentUser()` 会将 `id` 重映射为 username（'33528'），判定正确。**这证明：推理出的风险必须验证，一部分会是误报。**

### R4b 普通管理员删除周期的时间边界 🔍
- 推理：普通管理员只能删 `weekLabel > 当前周` 的周期，但"当前周"前后端各自计算，周末/时区边界可能不一致（前端放行后端拒绝，或反之）。
- 验证：周五 00:00 前后分别尝试删除。

## 家族五：整段解析/数据格式

### R5a 解析填入覆盖他人任务的作者信息 ⚠️（设计取舍）
- 推理：栏级/根任务级整段解析的 stamp 会把整棵子树 authorId 改为当前操作人，协作场景下他人任务被"静默改作者"。

### R5b 导入 fillNextWeek 目标周不存在 🔍
- 推理：Excel 导入勾选"下周计划填入下周"时，若下周周期不存在，行为未明（创建？丢弃？报错？）。

## 验证优先级

| 优先级 | 风险 | 理由 |
|---|---|---|
| P0 | R1b / R1c / R1d | 与已发生 bug 同家族，几乎必然触发 |
| P1 | R2a / R3c | 影响数据正确性（报错骚扰 / 静默覆盖） |
| P2 | R2c / R4b / R5b | 边界场景，需要环境配合验证 |
